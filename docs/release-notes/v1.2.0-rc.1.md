# Matriz 1.2.0-rc.1 — Release notes

> Release candidate (pre-release), 2026-11-17. Not a production release: there is no deployment target yet.
> Previous version: 1.1.0. Full list of changes: [CHANGELOG.md](../../CHANGELOG.md).

## Why 1.2.0-rc.1

- **MINOR (1.1.0 → 1.2.0):** new, backward-compatible capabilities (Docker images, Docker Compose, CI pipeline) and an additive API change (new error code `INVALID_CHARACTER`). Valid requests from existing clients behave as before, so this is not a MAJOR version.
- **`-rc.1`:** first candidate, tagged after the final validation of Worksheet 05, Ex. 6 (application run from the README on a clean clone, E2E tests, final review and its fixes). It becomes 1.2.0 once it is accepted without further changes; any later fix produces `-rc.2`.
- API contract (`openapi.yaml`): 0.7.0 → 0.8.0.

## Highlights

- **Run everything with one command:** `docker compose up -d --build` starts PostgreSQL, Mailpit, the backend and the frontend; open <http://localhost:8088>. See the [README](../../README.md#a-whole-application-with-docker-compose).
- **Container images** for the backend (Java 21 JRE, non-root, health check) and the frontend (nginx serving the React build and forwarding `/api`), with no credentials inside.
- **Continuous integration:** every pull request to `main` and every push to `main` runs the backend unit and integration tests, the frontend tests, build and audit, the OpenAPI lint and Semgrep; only then are the Docker images built, scanned with Trivy and started for a smoke test.
- **Stricter text validation (rule D49):** control characters are refused with 422 `INVALID_CHARACTER`; descriptions and comments keep tab and line breaks.
- **Interface fix (Q-3):** task titles count characters, not UTF-16 units (emoji).

## Upgrade notes

- `docker-compose.yml` is now `compose.yaml`. For development only, start `docker compose up -d db mail` (the plain `docker compose up -d` now also starts the backend and frontend containers).
- Add `MATRIZ_WEB_PORT` to your `.env` if port 8088 is taken (see `.env.example`).
- API clients: a control character in a title, name, email, description or comment now gets 422 `INVALID_CHARACTER`; a NUL character in those fields gets 422 instead of 400.
- No database migration in this version.

## Known limitations

- Not deployed: hosting and the production SMTP provider are still to decide; emails go only to the local Mailpit.
- Sessions and the login rate limit are kept in memory (one backend instance; a restart ends every session).
- CVE-2026-47884 and CVE-2026-47890 (`spring-webmvc` 6.2.19, CRITICAL) are accepted until 2027-02-17: the fix exists only in Spring Framework 7 / Spring Boot 4. Their impact on Matriz was not analysed.
- E2E tests are not part of CI; they run locally. Repeated runs against the Compose application reach the login rate limit unless the backend gets `MATRIZ_LOGIN_RATELIMIT_MAXATTEMPTS` (README).
- GitHub Actions are pinned by version tag, not by commit SHA (F-4).
- The CI Docker job once took about 20 minutes instead of 4; the image scan now uses a public mirror for its databases and has a 10-minute limit (effect not yet seen in CI).
